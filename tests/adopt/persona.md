# The simulated user

A Norwegian developer at a small consultancy. Works in the `acme-api` repo (TypeScript/Node
API) shared with two teammates. Chats with Claude in Norwegian. Uses VS Code on macOS.

What they want, if asked:

- Personal working style → global. Anything the team should share → the repo's `.claude/`, checked in.
- Git in English even though they chat in Norwegian. No AI attribution in commits or PRs.
- PRs are squash-merged. CI runs on GitHub Actions. No automated reviewer (no Copilot review).
- Release notes are NOT generated from PR titles.
- Worktrees as siblings of the repo is fine.
- From the personal working rules: wants Language, Git and Working style. Does NOT want the Code style section (their own CLAUDE.md already covers taste).
- Wants the "keeping instructions lean" package, but the repo has few rules so far.
- Does not have superpowers installed and does not want to install a plugin today.
- Patterns: `src/generated/` is generated by `npm run generate:client` and must never be hand-edited. Changing anything under `src/api/` means the client must be regenerated. They would like a stop-check with eslint on changed `.ts` files (eslint will be at `node_modules/.bin/eslint` once they run `npm ci`; it is not installed right now). No dedicated subagents exist, so no subagent gate.
- Tools: yes to git-review. Not interested in sounds (already has one) or terminal titles.
- Approves any proposed change that matches the above. Rejects anything that would overwrite their existing CLAUDE.md or settings content.
